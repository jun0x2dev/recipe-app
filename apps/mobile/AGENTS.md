# AGENTS.md

## 적용 범위

이 문서는 `apps/mobile` 아래의 모바일 앱 작업에 적용한다.

## 프로젝트 맥락

- 목표: iOS 우선 레시피 앱
- 런타임: React Native + Expo
- 언어: TypeScript
- 라우팅: Expo Router
- 테마: 라이트 모드와 다크 모드를 모두 지원

## 개발 규칙

- `app/` 라우트 파일은 얇게 유지한다.
- 라우트 파일에는 화면 조합과 라우트 파라미터 처리만 둔다.
- 재사용 가능한 UI는 `src/components`에 둔다.
- 레시피 관련 화면, 타입, mock 데이터, 상태는 `src/features/recipes`에 둔다.
- 공통 테마 유틸리티는 `src/theme`에 둔다.
- 화면 로직이 커질 경우 `App.tsx`에 직접 쌓지 않는다.
- 명시적인 도메인 타입과 typed props를 우선 사용한다.
- mock 데이터는 UI 컴포넌트와 분리한다.
- 여러 화면에서 공유되는 변경 가능한 상태가 필요해지기 전까지 전역 상태 라이브러리는 추가하지 않는다.
- 새 화면이나 주요 구조를 추가하면 `apps/mobile/README.md`의 프로젝트 구조도 함께 갱신한다.
- 작업 완료 여부가 바뀌면 루트 `TODO.md`를 함께 갱신한다.

## UI 규칙

- 모든 화면은 라이트 모드와 다크 모드에서 모두 동작해야 한다.
- 모바일 우선의 간결한 레이아웃을 사용한다.
- 이 앱은 마케팅 사이트가 아니므로 과한 히어로 섹션이나 랜딩 페이지식 구성을 피한다.
- 카드와 컨트롤의 border radius는 특별한 이유가 없으면 8px를 기준으로 한다.
- 중요한 상태는 색상만으로 표현하지 말고 가능한 경우 텍스트 라벨을 함께 사용한다.
- 현재 UI는 구조 검증용이다. 추후 모바일 UI 디자인 전면 교체를 전제로 한다.
- 색상, 간격, 폰트 크기, radius 같은 디자인 값은 점진적으로 `src/theme`의 토큰으로 분리한다.
- React Native에서는 CSS 파일을 `assets`에 분리하는 방식을 기본으로 쓰지 않는다.
- `assets`는 이미지, 아이콘, 폰트, 앱 아이콘, splash 같은 정적 파일을 둘 때 사용한다.

## 라우팅 규칙

- Expo Router를 기준으로 화면을 추가한다.
- `app/` 파일은 라우트 연결만 담당하고, 실제 화면 구현은 `src/features/*/screens`에 둔다.
- 상세 화면처럼 파라미터가 필요한 라우트는 `app/**/[id].tsx`에서 파라미터를 읽고 screen 컴포넌트에 명시적으로 전달한다.
